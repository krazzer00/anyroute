<h1 align="center">AnyRoute</h1>

<p align="center">Клиент Cisco AnyConnect для Windows с TUN и маршрутизацией по правилам — по процессам, доменам и адресам, как в Throne.</p>

---

## Возможности

- **Cisco AnyConnect (SSL/TLS + DTLS)** — собственный клиент на Go, без `vpnagent` и OpenConnect. Совместим с Cisco ASA и ocserv; правильно проходит двухфакторную аутентификацию ASA (форма challenge, `<opaque>`/auth-handle, сообщения с подстановками).
- **TUN через встроенный sing-box** и **правила маршрутизации**: `processName:`, `processPath:`, `domain:`, `full:`, `keyword:`, `regexp:`, `ip:`, `port:`. Списки «Через VPN», «Напрямую», «Блокировать», несколько профилей с переключением на лету — без переподключения и повторной 2FA.
- **Работает вместе с Throne** (и другими TUN-VPN): AnyRoute забирает только то, что должно идти в VPN, — сети сервера, адреса из правил и адреса доменов из правил. Узкие маршруты выигрывают у широких маршрутов Throne, поэтому интернет остаётся за Throne.
- **Сохранённые учётные данные**: пароль и TOTP-секрет хранятся в диспетчере учётных данных Windows. Выбираете сервер — логин, пароль и код 2FA подставляются сами.
- **Вкладки «Логи», «Приложения», «График»**: журнал с фильтрами, активные соединения по процессам с указанием, куда ушёл трафик, график скорости VPN и прямого трафика.
- **Служба Windows**: интерфейс работает без прав администратора и без UAC при каждом запуске. Зависание или падение интерфейса туннель не трогает.
- **Никаких «залипших» правил DNS**: при старте службы и перед каждым подключением AnyRoute находит и удаляет оставшиеся после сбоя правила NRPT, в том числе старые правила DualVPN.
- **Автообновление** из GitHub Releases. Установщик проверяется по SHA-256 и подписи ed25519 и ставится службой, без окна UAC.
- Тёмная тема, стекло (Acrylic) и неоновые акценты; работает и в Windows 10, и в Windows 11.

## Установка

1. Скачайте `AnyRoute-Setup-X.Y.Z.exe` из [последнего релиза](https://github.com/krazzer00/anyroute/releases/latest).
2. Запустите установщик: права администратора нужны один раз, чтобы зарегистрировать службу.
3. Добавьте сервер (кнопка «+»): адрес, группа (кнопка «↻ С сервера» запросит список у шлюза), логин и пароль, по желанию TOTP-секрет.

> Установщик не подписан коммерческим сертификатом, поэтому Windows SmartScreen при первом запуске может показать предупреждение: «Подробнее» → «Выполнить в любом случае». Обновления ставятся уже без этого.

## Правила маршрутизации

По одному правилу в строке, `#` — комментарий. Правила проверяются по порядку: **Блокировать → Напрямую → Через VPN → сети сервера → по умолчанию**.

| Правило | Что совпадает |
|---|---|
| `processName:Telegram.exe` | процесс по имени |
| `processPath:C:\Apps\tool.exe` | процесс по полному пути |
| `domain:corp.example`, `*.corp.example`, `corp.example` | домен и все поддомены |
| `full:jira.corp.example` | только это имя |
| `keyword:intra`, `regexp:^git\.` | подстрока или регулярное выражение в имени |
| `ip:10.0.0.0/8`, `192.168.1.5` | адрес или подсеть |
| `port:3389`, `port:1000-2000` | порт назначения |

Флажки профиля:
- **«Сети и DNS-зоны сервера → VPN»** — то, что выдал шлюз (split-include, split-DNS), идёт в VPN.
- **«Локальная сеть напрямую»** — подсети ваших сетевых адаптеров никогда не заворачиваются в VPN.
- **«По умолчанию»**: «Напрямую» — как обычный AnyConnect; «Через VPN» — весь трафик, кроме исключений.

## Как это устроено

```
AnyRoute.exe (интерфейс, права пользователя)
   │  \\.\pipe\anyroute (JSON, таймауты на каждый вызов)
   ▼
anyroute-service.exe (служба, LocalSystem)
   ├─ anyconnect: аутентификация, 2FA, CSTP/DTLS
   ├─ vpnstack: gVisor TCP/IP поверх туннеля
   └─ sing-box: TUN anyroute-tun, правила, DNS
        ├─ outbound «anyconnect» → vpnstack → VPN
        ├─ DNS шлюза через туннель + /32-маршруты для доменов из правил
        └─ outbound «direct» → физический адаптер
```

DNS: Windows направляет в AnyRoute только нужные зоны через одно правило NRPT с меткой `AnyRoute`. Метка гарантирует, что правило будет найдено и снято после любого сбоя.

## Диагностика

- **Журнал службы:** `%ProgramData%\AnyRoute\logs\service.log`. Пароли, коды, cookie и токены в журнале маскируются.
- **Отладочный уровень** (Настройки → Подробность журнала) пишет XML-обмен с шлюзом — с замаскированными секретами.
- **Подключение без интерфейса** (от администратора, служба при этом не должна быть подключена):
  ```
  anyroute-cli -host vpn.example.com -groups
  anyroute-cli -host vpn.example.com -group "Remote Access" -user ivan -hold 60s
  ```

## Сборка

Нужен Go (версия из `go.mod`). NSIS — только для установщика.

```powershell
powershell -ExecutionPolicy Bypass -File build\build.ps1 -Version 0.1.0
go test -tags with_gvisor ./...
```

Релиз собирается GitHub Actions по тегу `vX.Y.Z` (`.github/workflows/release.yml`).
