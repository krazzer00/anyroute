# AnyRoute — дизайн

Дата: 2026-10-06. Статус: утверждён пользователем, ожидает ревью текста.

## Цель

Удобный клиент Cisco AnyConnect (SSL/TLS) для Windows: **один** туннель в
режиме TUN, маршрутизация по правилам в стиле Throne (процессы, домены,
адреса), переключаемые профили маршрутизации, сохранённые учётные данные с
автоподстановкой, корректная 2FA (включая автогенерацию TOTP), трей, вкладки
«Логи / Приложения / График», автообновление из GitHub Releases. Основа
подключения — нативный Go-клиент из DualVPN (форк `tlslink/sslcon`).

Не входит: несколько одновременных туннелей, режим SOCKS5, PAC/системный
прокси, Linux/macOS, SAML/SSO, сертификатная аутентификация.

Платформа: Windows 10 (1809+) и Windows 11, x64.

## 1. Архитектура

Два процесса и канал между ними.

| Компонент | Права | Ответственность |
|---|---|---|
| `AnyRoute.exe` (GUI, Wails v2) | пользователь | окно, трей, профили серверов и маршрутизации, учётные данные (Windows Credential Manager), генерация TOTP, UI обновлений |
| `anyroute-service.exe` (служба) | LocalSystem | AnyConnect-клиент, встроенный sing-box (TUN, правила, DNS, статистика), очистка после сбоев, установка обновлений |
| `\\.\pipe\anyroute` | — | JSON по строке на кадр: запросы GUI → ответы и поток событий службы |

- Служба владеет туннелем: падение или зависание GUI его не трогает; после
  перезапуска GUI получает текущее состояние запросом `status` и подписывается
  на события.
- Канал: SDDL — полный доступ SYSTEM и администраторам, чтение-запись —
  интерактивным пользователям. Каждый запрос GUI имеет таймаут 5 с.
- Всё, что приходит от непривилегированного GUI, валидируется в службе
  (адреса, имена, правила, длины строк) до использования.

## 2. Подключение и 2FA

Поток:

1. Пользователь выбирает профиль сервера и жмёт «Подключить».
2. GUI достаёт логин, пароль из Credential Manager (если пароль не сохранён —
   спрашивает) и шлёт `connect{server, group, username, password, routingProfile}`.
3. Служба: очистка остатков (§5) → `InitAuth` (TLS, редиректы, список групп)
   → `PasswordAuth`.
4. Если сервер прислал challenge — событие `2fa_required`. GUI:
   - есть TOTP-секрет у профиля → генерирует код и отправляет `submit2fa`
     автоматически (один раз на challenge);
   - нет секрета или автокод отклонён → окно ввода кода.
   Ожидание кода прерывается отключением; повторный challenge после неверного
   кода снова открывает окно (логика `Submit2FA` из DualVPN сохраняется).
5. `SetupTunnel` (CSTP + DTLS) → запуск sing-box с TUN и outbound `anyconnect`
   → событие `connected` с IP, DNS, split-include/split-DNS сервера.

Сохраняется всё, что в DualVPN проверено на живой ASA: тело `<device-id>`,
форма ответа на challenge (`<password>`, условный `<username>`, без
`<group-select>`, дословный `<opaque>`), подстановка `param1` в сообщения,
следование редиректам, группа и учётные данные одним запросом. User-Agent в
формате `AnyConnect Windows <версия>` — и для auth-запросов, и для `CONNECT`.

### Профиль сервера

`{id, name, host, group, username, savePassword, hasTotp, routingProfileId}`
хранится в `%APPDATA%\AnyRoute\servers.json`. Пароль и TOTP-секрет — только в
Credential Manager: `AnyRoute/<id>/password`, `AnyRoute/<id>/totp`. Служба
секреты не хранит и не логирует. Список групп подгружается с сервера кнопкой
«↻ с сервера».

## 3. Маршрутизация

Движок — sing-box, встроенный как Go-библиотека (версия зафиксирована в
`go.mod`). Своя часть — outbound типа `anyconnect`: TCP/UDP-соединения
открываются в gVisor netstack, который обменивается пакетами с CSTP-туннелем.

### Профиль маршрутизации

```json
{
  "id": "default", "name": "Default",
  "defaultOutbound": "vpn" | "direct",
  "serverRoutesToVpn": true,
  "lanDirect": true,
  "vpn": ["domain:corp.example", "10.0.0.0/8"],
  "direct": ["processName:Telegram.exe"],
  "block": []
}
```

Файлы: `%APPDATA%\AnyRoute\profiles\<id>.json`. При первом запуске создаётся
`Default` (`defaultOutbound: direct`, `serverRoutesToVpn: true`).

### Синтаксис правил (по строке, `#` — комментарий)

| Правило | Значение | sing-box |
|---|---|---|
| `processName:x.exe` | имя процесса без учёта регистра | `process_name` |
| `processPath:C:\...\x.exe` | полный путь | `process_path` |
| `domain:example.com`, `domain:*.example.com`, `example.com` | домен и поддомены | `domain_suffix` |
| `full:host.example.com` | только точное имя | `domain` |
| `keyword:abc` | подстрока в имени | `domain_keyword` |
| `regexp:...` | регулярное выражение | `domain_regex` |
| `ip:1.2.3.0/24`, `1.2.3.4`, `1.2.3.0/24` | адрес/подсеть | `ip_cidr` |
| `port:443`, `port:1000-2000` | порт назначения | `port` / `port_range` |

Ошибочная строка подсвечивается в редакторе с причиной; профиль с ошибками
не сохраняется.

### Порядок решения

Порядок применяется к трафику, попавшему в TUN AnyRoute (см. «Совместная
работа с Throne»).

1. Адрес VPN-шлюза → напрямую (всегда; соединение CSTP/DTLS к тому же
   привязано к физическому интерфейсу).
2. **Блокировать**.
3. **Напрямую**.
4. **VPN**.
5. Если `serverRoutesToVpn`: split-include и зоны split-DNS сервера → VPN.
6. Если `lanDirect`: частные и link-local сети → напрямую.
7. `defaultOutbound`.

### Совместная работа с Throne и другими TUN-VPN

Обязательное требование: у пользователя постоянно включён Throne (sing-box
TUN `throne-tun`, адрес `172.19.0.0/24`), который забирает публичный интернет
десятками широких маршрутов (`/3`…`/8`) и не трогает частные сети. AnyRoute не
должен с ним конфликтовать, поэтому:

- **AnyRoute не захватывает весь трафик.** sing-box TUN поднимается с
  `auto_route: true` и явным `route_address` — только то, что должно идти в
  VPN: split-include сервера (если `serverRoutesToVpn`), CIDR из списка «VPN»,
  DNS-серверы шлюза, адрес DNS-форвардера и динамические host-маршруты (/32)
  для доменов, идущих в VPN (см. DNS). Узкие маршруты по правилу longest
  prefix match выигрывают у широких маршрутов Throne; интернет остаётся за
  Throne. `strict_route` выключен.
- **`defaultOutbound: vpn`** добавляет `0.0.0.0/1` и `128.0.0.0/1`. При
  активном Throne его более узкие маршруты по-прежнему перехватывают
  публичный интернет — UI предупреждает об этом.
- **Адрес TUN** выбирается из кандидатов (`172.29.254.0/30`,
  `100.127.254.0/30`, `198.18.254.0/30`) — первый, не пересекающийся с
  адресами локальных интерфейсов и split-include сервера; имя интерфейса
  `anyroute-tun`.
- **Соединения к VPN-шлюзу** (TLS/DTLS) и outbound `direct` привязываются к
  физическому интерфейсу маршрута по умолчанию (`IP_UNICAST_IF`), а не
  уходят в чужой TUN.
- **Правила по процессам и доменам** действуют для трафика, попавшего в TUN
  AnyRoute. Для доменов из списка «Напрямую» внутри сетей VPN домен берётся
  сниффингом (TLS SNI, HTTP Host, QUIC).

### DNS

Собственный DNS-форвардер службы слушает адрес `<TUN>.2:53` внутри подсети
TUN AnyRoute. Запросы к нему направляет NRPT: одно правило с комментарием
`AnyRoute` и списком пространств имён — зоны split-DNS сервера, домены из
списка «VPN» (а при `defaultOutbound: vpn` — `.`). Форвардер:

- имена из списка «Напрямую» разрешает системным DNS через физический
  интерфейс;
- остальные — DNS-серверами шлюза через туннель (UDP, откат на TCP), то есть
  через gVisor-стек VPN, минуя таблицу маршрутов;
- для каждого A-ответа на домен, идущий в VPN, до отправки ответа добавляет
  /32-маршрут в `anyroute-tun` (через `winipcfg`, без netsh). Маршруты живут
  до отключения и исчезают вместе с адаптером.

NRPT ставится и снимается одним вызовом PowerShell с таймаутом и
`WaitDelay`, вне пути ответа GUI; при старте службы и перед подключением
правила с комментарием `AnyRoute` и `DualVPN:*` удаляются (см. §5).

### Смена профиля

Переключение профиля при активном подключении перезапускает только sing-box;
CSTP-сессия и пройденная 2FA сохраняются. Редактирование активного профиля
применяется по «Сохранить».

## 4. Интерфейс

- Окно без системной рамки, свой заголовок (перетаскивание, «свернуть»,
  «в трей»). Крестик сворачивает в трей.
- Слева — список серверов и «+». Сверху — выбранный сервер, выпадающий список
  профиля маршрутизации, кнопка «Подключить/Отключить», статус, время
  подключения, выданный IP.
- Вкладки:
  - **Логи** — уровни (INFO/WARN/ERROR/OK), фильтр по уровню и тексту,
    копирование, буфер 5000 строк;
  - **Приложения** — процессы с активными соединениями: адрес/домен, outbound
    (VPN/напрямую/заблокировано), объём, длительность; обновление раз в секунду;
  - **График** — скорость приёма/отдачи за последние 5 минут, отдельно VPN и
    напрямую (uPlot).
- Редактор профилей маршрутизации — диалог по образцу Throne: название,
  outbound по умолчанию, флажки, три поля «VPN / Напрямую / Блокировать»,
  кнопка «Как пользоваться» со справкой по синтаксису.
- Настройки: автозапуск при входе, проверка обновлений, уровень логов,
  «Отключить эффекты прозрачности».
- Трей: значок отражает состояние (подключено/подключается/отключено/ошибка);
  меню — статус, подключение к любому серверу, подменю профиля маршрутизации,
  «Отключить», «Показать», «Выход».
- Окно 2FA: поле кода, автофокус, Enter — отправка, текст сообщения сервера.

## 5. Надёжность: зависания и остатки после сбоев

- **GUI никогда не блокируется.** Все биндинги Wails асинхронные (результат
  приходит событием); вызовы службы — с таймаутом 5 с; каждый пункт трея
  обрабатывается в своей горутине, «Показать» и «Выход» работают всегда.
- **Служба:** одна горутина-исполнитель команд (connect/disconnect/switch
  профиля), статус — атомарный снимок, читается без блокировки исполнителя.
- **Отключение с дедлайном:** штатное (остановка sing-box, закрытие CSTP) —
  до 5 с, затем принудительное закрытие сокетов и устройства. Повторное
  отключение идемпотентно.
- **Внешние утилиты** (netsh, PowerShell) в рабочем цикле не используются.
  Где без них нельзя (установка и снятие NRPT) — только через обёртку с
  таймаутом и `cmd.WaitDelay`, вне пути ответа GUI.
- **После аварии:** маршруты и WFP-фильтры sing-box исчезают вместе с
  процессом/адаптером. Дополнительно при старте службы и перед каждым
  подключением выполняется `cleanup`: удаление зависшего адаптера AnyRoute,
  правил NRPT с комментарием `AnyRoute*` и унаследованных `DualVPN:*`.
- **SCM recovery:** служба перезапускается при падении (1-й и 2-й сбой —
  через 5 с).
- **Служба не отвечает:** GUI показывает статус и кнопку «Перезапустить
  службу» (DACL службы при установке разрешает интерактивным пользователям
  start/stop).
- **Выход из приложения** спрашивает, отключать ли туннель; по умолчанию —
  отключать.

## 6. Внешний вид

- Тёмная тема: основа почти чёрная с синим отливом; полупрозрачные
  «стеклянные» карточки (`backdrop-filter: blur`), тонкая светящаяся голубая
  обводка (`#22d3ee`–`#38bdf8`), неоновые разделители и акценты (активная
  вкладка, кнопка подключения пульсирует при подключении), график — неоновые
  линии с градиентной заливкой. Статусы: голубой — подключено, янтарный —
  подключается, красный — ошибка.
- Windows 11: `BackdropType: Acrylic` (Wails) и `DWMWA_WINDOW_CORNER_PREFERENCE
  = ROUND`.
- Windows 10: скругление `SetWindowRgn`; размытие фона —
  `SetWindowCompositionAttribute(ACCENT_ENABLE_ACRYLICBLURBEHIND)`; при
  проблемах (лаги перетаскивания) — имитация стекла внутри окна без
  просвечивания рабочего стола. Тот же режим включает настройка «Отключить
  эффекты прозрачности».
- Текст — контраст WCAG AA; свечение только на линиях и акцентах.
- До реализации UI утверждается макет главного окна и редактора маршрутов.

## 7. Репозиторий, сборка, автообновление

- Публичный `github.com/krazzer00/anyroute`, лицензия GPLv3 (требование
  sing-box), история с нуля.
- **CI** (`.github/workflows/ci.yml`, `windows-latest`, на push и PR): `go vet`,
  тесты, сборка GUI и службы.
- **Релиз** (`release.yml`, на тег `vX.Y.Z`): версия из тега → сборка GUI и
  службы (`-X main.version`) → загрузка wintun → NSIS-установщик → SHA-256 →
  подпись ed25519 закрытым ключом из `secrets.UPDATE_SIGNING_KEY` → GitHub
  Release с ассетами `AnyRoute-Setup-X.Y.Z.exe`, `AnyRoute-Setup-X.Y.Z.exe.sig`,
  `latest.json` (`version`, `url`, `sha256`, `notes`).
- **Автообновление:** GUI проверяет `latest.json` последнего релиза при старте
  и раз в 6 часов (отключаемо). Есть новая версия — плашка с описанием
  изменений. «Обновить» → служба скачивает установщик и подпись, сверяет
  SHA-256 и подпись встроенным открытым ключом, предупреждает и отключает
  туннель, запускает установщик тихо (`/S`). Установщик останавливает службу,
  заменяет файлы, запускает службу и GUI. Без UAC. Любое несовпадение подписи —
  отказ и запись в журнал; URL загрузки — только `github.com/krazzer00/anyroute`.
- Authenticode-сертификата нет: первая ручная установка вызывает
  предупреждение SmartScreen; Smart App Control (если включён) может
  блокировать неподписанные exe — это ограничение среды.

## 8. Защита от утечки секретов

- Код переносится из DualVPN пофайлово, без истории. Перед первым коммитом —
  поиск реальных адресов серверов, логинов, групп и внутренних зон из
  локальных конфигов и логов; в репозитории только заглушки (`vpn.example.com`).
- `.gitignore` с первого коммита: пользовательские конфиги и профили, логи,
  `bin/`, `*.key`, `*.pem`, `*.pfx`, `*.p12`, `.env*`, дампы.
- gitleaks: pre-commit хук и job в CI на каждый push/PR; на репозитории
  включены secret scanning и push protection.
- Ключ подписи обновлений генерируется вне репозитория, загружается только в
  GitHub Secrets; в код попадает лишь открытый ключ; копия закрытого ключа
  передаётся пользователю для хранения.
- Логи: маскирование паролей, TOTP-кодов и секретов, cookie `webvpn`, session
  token — во всех уровнях, включая отладочный XML.
- Перед первым push — полный прогон gitleaks и отчёт пользователю.

## 9. Тестирование

- Модульные: `rules` (разбор, ошибки, порядок, сборка опций sing-box),
  `profiles`, `secrets` (TOTP по векторам RFC 6238), `update` (подпись,
  SHA-256, сравнение версий, отказ на чужой URL), `ipc` (валидация, таймауты),
  `logx` (маскирование).
- Интеграционные на `mockasa`: auth → 2FA → CSTP → outbound `anyconnect` →
  хост внутренней сети; неверный код → повторный challenge; отключение во
  время ожидания 2FA; отключение укладывается в дедлайн.
- `anyroute-cli` — проверка на живом ASA (группы, вход, 2FA, разрешение имён).
- Ручная приёмка на Windows: TUN, правила по процессу/домену, переключение
  профиля без переподключения, аварийное завершение службы → чистый повторный
  старт, обновление с предыдущего релиза.
