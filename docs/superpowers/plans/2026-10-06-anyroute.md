# AnyRoute Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Windows-клиент Cisco AnyConnect с TUN через встроенный sing-box, правилами в стиле Throne, сохранёнными учётными данными, 2FA/TOTP, службой, GUI на Wails и автообновлением из GitHub Releases.

**Architecture:** Служба `anyroute-service` (LocalSystem) держит AnyConnect-сессию (форк sslcon из DualVPN) и sing-box (TUN `anyroute-tun` с узкими `route_address`, outbound `anyconnect` поверх gVisor-стека, DNS-транспорт `anyconnect` с host-маршрутами). GUI `AnyRoute.exe` (Wails v2, права пользователя) общается со службой по `\\.\pipe\anyroute`. Совместная работа с Throne — за счёт узких маршрутов и привязки к физическому интерфейсу.

**Tech Stack:** Go 1.26, sing-box v1.14.2 (теги `with_gvisor`), github.com/sagernet/gvisor, Wails v2.13, fyne.io/systray, golang.zx2c4.com/wireguard/windows/tunnel/winipcfg, github.com/danieljoos/wincred, Go Microsoft/go-winio (named pipe), golang.org/x/sys/windows/svc, NSIS, GitHub Actions, gitleaks, uPlot.

Спецификация: `docs/superpowers/specs/2026-10-06-anyroute-design.md`.

## Этап 1. Ядро подключения

### Task 1.1: Модуль и перенос протокола
- [ ] `go mod init github.com/krazzer00/anyroute`; зависимости: sing-box v1.14.2.
- [ ] Перенести `proto`, нужные функции `utils` и логгер из `tlslink/sslcon` в `internal/anyconnect` (MIT, указать источник в заголовке файлов и в `NOTICE`), убрать все process-глобалы (`base.Cfg` → поля `Client`/`Config`).
- [ ] Перенести форк `auth.go`, `profile.go`, `session.go`, `tunnel.go` из DualVPN: выкинуть TUN/routing/NRPT-код, `Mode`, `TunnelSetup`; оставить packet flow (`ReadPacket/WritePacket`, `Done`, `Info`). User-Agent `AnyConnect Windows <ver>` для всех запросов, включая `CONNECT`.
- [ ] Логирование через интерфейс `Logger`; маскирование `password`, `answer`, кодов, `webvpn`, `session-token`, `X-DTLS-Master-Secret`; убрать вывод SessionToken.
- [ ] Перенести тесты `auth_test.go`, `group_select_test.go` и `mockasa`; `go test ./internal/anyconnect/... ./internal/mockasa/...` зелёные.

### Task 1.2: vpnstack
- [ ] `vpnstack.New(io PacketIO, addr netip.Addr, mtu int)` на `github.com/sagernet/gvisor`: inject/extract горутины, `DialContext(ctx, network, addr)`, `ListenPacket`, `Close`.
- [ ] Тест: две `vpnstack` соединены каналами «трубой» с echo-сервером в стеке на другой стороне — TCP и UDP echo.

### Task 1.3: Outbound и DNS-транспорт sing-box
- [ ] `engine/outbound.go`: тип `anyconnect`, опции `{}`; стек берётся из `context` (`service.ContextWith[*vpnstack.Stack]`); `DialContext` (TCP/UDP), `ListenPacket`.
- [ ] `engine/dnstransport.go`: тип `anyconnect`; опции `{servers}`; обмен через `vpnstack` (UDP, при TC — TCP); после ответа — колбэк `OnAnswer(ips)` для host-маршрутов.
- [ ] `engine/config.go`: `Build(Params)` → `option.Options` (TUN `anyroute-tun`, `stack: mixed`, `auto_route`, `route_address`, `dns_mode: disabled`; outbounds `vpn`/`direct`/`block`; `route.find_process`, `auto_detect_interface`, `default_domain_resolver`; правила: sniff, hijack-dns для `<tun>.2:53`, шлюз → direct, далее из `rules.Compile`; DNS servers `vpn-dns` (anyconnect) и `local`; DNS rules).
- [ ] Тест сборки конфигурации: JSON-снимок для типового профиля; `box.New` с конфигом без TUN-инбаунда проходит.

### Task 1.4: Правила
- [ ] `rules.Parse(kind, text)` → `[]Rule`, ошибки с номером строки; синтаксис из спецификации.
- [ ] `rules.Compile(profile, serverInfo)` → `RouteRules`, `RouteAddress []netip.Prefix`, `NRPTNamespaces []string`, `DNSRules`.
- [ ] Табличные тесты: каждый префикс, `*.`-домены, голый домен, голый IP/CIDR, порт/диапазон, комментарии, ошибки; порядок block → direct → vpn → сервер → lan → default; `defaultOutbound: vpn` даёт `0.0.0.0/1,128.0.0.0/1` и NRPT `.`.

### Task 1.5: Системная интеграция Windows
- [ ] `execx.Run(ctx, timeout, name, args...)` с `WaitDelay=2s`, `CREATE_NO_WINDOW`.
- [ ] `nrpt`: `Apply(comment, namespaces, server)` одним вызовом PowerShell; `RemoveByCommentPrefix(prefixes...)`; `Leftovers()` — чтение `HKLM\SYSTEM\CurrentControlSet\Services\Dnscache\Parameters\DnsPolicyConfig` без PowerShell.
- [ ] `netx`: физический интерфейс по умолчанию (маршрут `0.0.0.0/0` с минимальной метрикой, не TUN), `PickTunPrefix(exclude []netip.Prefix)`.
- [ ] `hostroutes`: `Add/RemoveAll` на LUID интерфейса `anyroute-tun`, учёт добавленных для повторного применения после перезапуска box.
- [ ] `cleanup.Run()`: NRPT `AnyRoute*` и `DualVPN:*`, зависший адаптер `anyroute-tun`.
- [ ] Тесты без прав: разбор вывода/реестра, выбор подсети.

### Task 1.6: Ядро службы
- [ ] `core.Core`: состояние (`idle|connecting|auth|2fa|connected|disconnecting|error`), атомарный снимок, очередь команд в одной горутине, события в шину.
- [ ] Connect: cleanup → anyconnect.Client (dialer привязан к физ. интерфейсу) → 2FA ожидание → Tunnel → vpnstack → engine.Start → NRPT.
- [ ] Disconnect с дедлайном 5 с, затем принудительно; NRPT Remove; повтор идемпотентен.
- [ ] SwitchProfile: engine.Reload, повтор host routes, NRPT пересчитать.
- [ ] Тесты на mockasa: connect → 2FA → connected (без TUN: engine с фиктивным TUN отключён флагом `Params.NoTun` для тестов) → disconnect ≤ 5 с; отмена во время 2FA; неверный код → повторный challenge.

### Task 1.7: IPC и служба Windows
- [ ] Протокол: `hello`, `status`, `connect`, `disconnect`, `submit2fa`, `setProfile`, `logs`, `stats`, `apps`, `update.apply`, `service.version`; события `state`, `log`, `2fa`, `stats`.

- [ ] `cmd/anyroute-service`: `install` (SCM, recovery, DACL для старта/остановки пользователями), `uninstall`, `run` (консоль), обработка Stop/Shutdown → disconnect + cleanup.
